## Plan: template advertentie weghalen en launch-flow ombouwen\n\n### Wat er misgaat\nDe fout zit nog steeds in het opnieuw opbouwen van `object_story_spec` in `meta-upload-creative`.\n\nWat ik heb bevestigd:\n- de template creative wordt wel geladen\n- de launch start ook echt met `template_used: true`\n- Meta weigert daarna nog steeds de nieuwe creative met:\n  - `adcreatives: Invalid parameter — object_story_spec ... (100/1443048)`\n\nDus het probleem is niet de selector zelf, maar dat we nog steeds een nieuwe creative construeren in plaats van een bestaande geldige ad-context echt te dupliceren.\n\n### Nieuwe richting\nIk ga de zichtbare **template advertentie** uit de UI halen en de backend ombouwen naar een **auto-copy flow**:\n\n1. De gebruiker kiest alleen nog:\n   - campagne\n   - ad set\n   - lead formulier\n2. De backend zoekt automatisch een geschikte bestaande advertentie als bron.\n3. In plaats van `act_{account}/adcreatives` met handgemaakte `object_story_spec` te posten, maken we een kopie van een bestaande advertentie via Meta’s **Ad Copies API** (`/{ad-id}/copies`).\n4. Alleen de velden die we willen wijzigen worden overschreven via `creative_parameters`.\n\nDat sluit beter aan op Meta’s eigen copy-mechanisme en vermijdt precies het deel dat nu kapot gaat.\n\n### Wat ik ga aanpassen\n\n#### 1) UI vereenvoudigen\nVerwijderen van de template-flow uit de app:\n- `src/components/ad-launcher/MetaSelectors.tsx`\n  - `template_ad_id` uit `MetaSelection`\n  - template dropdown verwijderen\n  - template resource loading verwijderen\n- `src/pages/client-workspace/AdLauncherTab.tsx`\n  - state vereenvoudigen\n  - `template_ad_id` niet meer meesturen\n\n#### 2) Resource endpoint opschonen\n- `supabase/functions/meta-list-resources/index.ts`\n  - `template_ads` en `template_ad_detail` verwijderen als ze niet meer nodig zijn\n  - alleen campagne / ad set / leadform resources behouden\n\n#### 3) Launch-strategie vervangen\n- `supabase/functions/meta-upload-creative/index.ts`\n  - huidige `buildPayloadFromTemplate` verwijderen\n  - geen nieuwe `object_story_spec` meer construeren\n  - automatische bron-ad selectie toevoegen, met prioriteit:\n    1. zelfde ad set\n    2. geldige lead gen advertentie\n    3. zelfde page / lead form waar mogelijk\n  - nieuwe advertentie maken via `/{source_ad_id}/copies`\n  - `creative_parameters` gebruiken voor:\n    - nieuwe afbeelding/video\n    - primary text / headline / description\n    - multiple text options indien ondersteund in deze copy-flow\n    - status = `PAUSED`\n\n#### 4) Robuuste fallback bouwen\nAls Meta voor dit specifieke ad type geen meerdere tekstvarianten accepteert in de copy-flow:\n- duidelijke foutmelding teruggeven met reden\n- automatisch terugvallen op een veilige enkel-tekst launch of expliciete fallback voorbereiden\n- geen stille “success” meer als varianten gestript worden\n\n#### 5) Resultaat teruglezen en controleren\n- na creatie de nieuwe ad/creative teruglezen uit Meta\n- controleren welke velden echt zijn opgeslagen\n- `fetch-meta-ads` zo nodig uitbreiden zodat de app meerdere tekstvarianten ook echt kan tonen\n\n### Technische details\n```text\nOud:\nUI template selector -> template creative ophalen -> nieuwe adcreative posten -> object_story_spec fout\n\nNieuw:\nUI zonder template selector -> backend kiest automatisch source ad -> {ad-id}/copies -> creative_parameters override -> ad gepauzeerd aanmaken\n```\n\nBelangrijk verschil:\n- we stoppen met zelf reconstrueren van verborgen creative-context\n- we leunen op Meta’s eigen duplicatiepad\n- daardoor blijven placement-, profiel- en interne creative-instellingen intact\n\n### Bestanden\n- `src/components/ad-launcher/MetaSelectors.tsx`\n- `src/pages/client-workspace/AdLauncherTab.tsx`\n- `supabase/functions/meta-list-resources/index.ts`\n-
